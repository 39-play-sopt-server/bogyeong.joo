# 1. final / static / static final
- final: 초기화한 변수에 다른 값을 재할당할 수 없도록 합니다. 참조 변수에 사용하면 다른 객체로 바꿀 수 없지만, 객체 내부의 상태까지 변경 불가능해지는 것은 아닙니다. 변수가 아닌 경우 메서드에는 오버라이딩 금지, 클래스에는 상속 금지 의미로 사용합니다.
- static: 객체가 아닌 클래스에 속하도록 합니다. static 필드는 같은 클래스의 객체들이 공유하고, static 메서드는 객체를 생성하지 않고 호출할 수 있습니다.
- static final: 클래스에 속하면서 재할당할 수 없는 값을 선언합니다. 주로 공통 "상수"를 표현할 때 사용합니다.
  실제로 변경되지 않아야 하는 ID,작성자,작성 시각(추가된 필드입니다.) 에 final을 사용했습니다. main()은 객체를 생성하지 않고 실행되는 진입점이므로 static 메서드입니다.

# 2. Java의 Generic 타입
Generic은 클래스나 메서드에서 사용할 타입을 매개변수로 지정하는 기능입니다.
예를 들어 List<Post>는 게시글을 담는 목록이고, ApiResponse<Post>는 게시글을 데이터로 반환하는 응답입니다.
Generic을 사용하면 잘못된 타입의 사용을 컴파일 단계에서 확인할 수 있고, 값을 꺼낼 때 불필요한 형변환을 줄일 수 있습니다. 같은 구조를 여러 타입에 재사용할 수 있다는 장점도 있습니다.

# 3. primitive type과 wrapper class
- primitive type: int, long, boolean 등의 기본 타입입니다. 기본값 자체를 다루며 **null을 가질 수 없습니다.**
- wrapper class: Integer, Long, Boolean처럼 기본 타입에 대응하는 클래스입니다. **객체로 다루며 null을 표현할 수 있습니다.**
  일반적인 계산이나 필수 숫자 값에는 primitive type을 사용하고, 값이 없음을 null로 표현하거나 컬렉션·Generic의 타입 인자로 사용할 때는 wrapper class를 사용합니다.
  현재 게시글 ID는 long을 사용하지만, 저장소는 Generic에 기본 타입을 사용할 수 없으므로 Map<Long, Post>로 선언했습니다. Java는 둘 사이의 자동 변환을 지원하지만, null인 wrapper를 기본 타입으로 변환하면 아마 예외가 발생하는걸로 알고 있습니다..

# 4. 아키텍처의 각 요소 또는 계층은 어떤 역할과 책임을 가지는지 구체적인 설명
가장 익숙한 레이어드 구조로 아키텍쳐를 선정했으며 이후 과제를 진행하면서 심화 아키텍쳐로 리펙토링 해볼 예정입니다!! (처음 배운 아키텍쳐들로 바로 적용하기엔 너무 힘들었습니다..ㅜㅜ) 아키텍쳐 계층과 역할 및 책임은 다음과 같이 설정하였습니다.
- Main: 필요한 객체를 생성하고 연결합니다. 클라이언트의 메뉴를 반복하며 선택한 기능을 Controller에 요청합니다.
- PostView: 입력 안내와 재입력 흐름을 관리하고 PostInput과 PostOutput을 연결합니다.
- PostInput / PostOutput: 각각 콘솔 입력과 값의 해석, 화면 출력을 담당합니다.
- PostController: 요청을 Service에 전달하고, 처리 결과나 예외를 공통 응답 객체로 변환합니다.
- PostService: 게시글 생성·조회·수정·삭제의 처리 순서를 조율하고 존재 여부를 확인합니다.
- Post: 게시글의 상태를 관리합니다. 제목·본문 등의 값을 검증하고, 모든 검증이 끝난 뒤 자신의 상태를 수정합니다.
- PostRepository / InMemoryPostRepository: 저장소 접근 계약과 실제 저장 구현을 분리합니다. 구현체는 HashMap으로 게시글을 관리합니다.
- PostIdGenerator: 게시글의 고유 ID를 생성합니다.
- ApiResponse: 성공 여부, 코드, 메시지, 데이터를 담아 클라이언트가 일관된 방식으로 응답을 처리하도록 합니다.
